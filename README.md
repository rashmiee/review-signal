# Review Signal

Review Signal posts a deterministic pull request review brief as a GitHub PR
comment. It is intentionally small: path-aware rules, Rails-friendly defaults,
basic test signal, and one stable upserted comment.

It is not an AI reviewer and it does not execute code from the pull request.

## Usage

```yaml
name: Review Signal

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: write
  issues: write

jobs:
  brief:
    runs-on: ubuntu-latest
    steps:
      - uses: rashmiee/review-signal@v0.1.0
        with:
          preset: rails
          github-token: ${{ secrets.GITHUB_TOKEN }}
          # config-path: .github/review_signal.yml
```

## Inputs

| Input | Default | Description |
| --- | --- | --- |
| `github-token` | `${{ github.token }}` | Token used for PR metadata, Contents API config reads, and comment upsert. |
| `preset` | `rails` | Built-in preset: `rails` or `default`. |
| `config-path` | blank | Repo-relative YAML file fetched through GitHub Contents API from the PR base ref. |

## Config Loading Model

The GitHub Action does not checkout the consumer repository. In Action mode,
`config-path` is fetched through the GitHub Contents API from the trusted PR
base ref.

```text
built-in preset -> consumer YAML from pull_request.base.sha
```

The changed file list still comes from the pull request API, because those are
the files under review. Only the configuration is read from the trusted base
branch state.

For local CLI usage, `--config` reads from the local filesystem:

```bash
GITHUB_TOKEN=$(gh auth token) \
  bundle exec bin/review-signal \
  --repo OWNER/REPO \
  --pr 123 \
  --preset rails \
  --config ./tmp/custom_rules.yml \
  --dry-run
```

## Rule Format

Rules are path-only in v0.1.

```yaml
rules:
  - id: migration
    when:
      any_path: "db/migrate/**"
    severity: high
    message: "Schema change detected. Verify migration safety, rollback, and data backfill."
    review_focus:
      - "Confirm rollback path."
      - "Check for NOT NULL columns without a backfill."
```

Override rules with the same `id` replace built-in rules. New ids are appended.

## Security Model

Review Signal:

- Calls GitHub REST API only: PR metadata, changed file list, Contents API, and comments.
- Does not checkout the pull request branch.
- Does not execute code from the pull request.
- Fetches override config from the PR base ref, not the PR head.

### `pull_request` vs `pull_request_target`

The recommended default is `pull_request`. It is safer, but GitHub usually
downgrades write permissions for fork PRs, so comments may not be posted for
forked contributions.

Public repositories that need fork PR comments can use `pull_request_target`,
but only with the same trust boundary:

- Do not checkout the PR branch ref.
- Do not run `uses: ./` from the PR head.
- Do not execute scripts from the PR.

Review Signal only needs API calls. Keep it that way.
